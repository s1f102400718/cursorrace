# Cursor Run

カーソルそのものが自機のタイムアタック。障害物をよけてゴールまでのタイムを競う、ブラウザで動くゲームです。

- **デイリー**: 毎日 0:00（日本時間）に全員共通の新しいコース。その日のランキングを競う
- **ゴースト**: ランキングの相手の走りと並んで走れる。リプレイで見ることもできる
- **固定コース** NORMAL / HARD / EXTREME、要素を1つずつ試せる **LAB**
- **ONLINE**: 友だちと障害物を置き合ってから走る対戦（部屋の URL を送って集まる）

マウスかトラックパッドで遊ぶ作りです（タッチ操作には向きません）。

## あそびかた

1. カーソルがそのまま自機。緑のパッドに置いて待つとスタート
2. 壁と赤いものに触れたら、直前のパッドまで戻ってやり直し。タイムは止まらない
3. カーソルが部屋（画面）の外に出ても同じ
4. 黄色い出口で次の部屋へ。市松模様がゴール

| キー | |
|---|---|
| Enter / 1–3 / 4 | デイリー / 固定コース / ONLINE |
| R / B / M | リスタート / ランキング / メニュー |
| G / W / C | ゴーストの表示 / リプレイ / 結果をコピー |
| S / , . | 音の入切 / 音量 |
| V / [ ] / X | 画面の振動 / その強さ / 立体表示 |
| N / L / H | 名前 / LAB / あそびかた |

## 手元で動かす

```
npm install
node server.js        →  http://localhost:8080
```

`index.html` をブラウザで直接開いても遊べます（ランキングはその端末だけ、ONLINE は使えません）。

## 公開する

先に `node scripts/build-web.js <公開先のURL>` で `dist/` を作ります。URL を渡すと、SNS で共有したときの画像が正しく出ます。

**A. 置くだけ（`dist/web/`）** — GitHub Pages・Cloudflare Pages・Netlify など、ファイルを置くだけの場所に `dist/web/` の中身を置く。デイリー・固定コース・自己ベスト・ゴースト（自分の）・リプレイは動く。ランキングはその端末の中だけで、ONLINE は使えない。

**B. サーバーつき（`dist/server/`）** — 共有ランキングと ONLINE が使える。Node.js の動く場所（サポート中の版。22 など）に `dist/server/` を置いて

```
npm ci --omit=dev
node server.js
```

または `docker build -t cursor-run . && docker run -p 8080:8080 -v cursorrun-data:/data cursor-run`。記録は `DATA_DIR`（既定 `./data`、コンテナでは `/data`）に保存されるので、**消えない置き場を割り当てる**こと。

| 環境変数 | |
|---|---|
| `PORT` | 待ち受けるポート（既定 8080） |
| `DATA_DIR` | 記録の保存先 |
| `HOST` | 待ち受けるアドレス。トンネルやリバースプロキシを同じ機械で動かすなら `127.0.0.1`（外から直接つながせない） |
| `TRUST_PROXY` | 相手の接続元をどこから取るか。PaaS の入口が 1 つなら `1`（X-Forwarded-For の後ろから数える）。Cloudflare（Tunnel を含む）の後ろなら `cf`。**外から直接つながる構成では設定しない**（接続元を偽って回数の上限をすり抜けられる） |
| `ADMIN_TOKEN` | 設定すると管理用 API が有効になる。16 文字以上のランダムな文字列（短いと無効のまま） |
| `FRAME_ANCESTORS` | このページを枠（iframe）に埋め込んでよい相手。既定は埋め込み不可 |

自分の PC から Cloudflare Tunnel で一時的に出すなら `start.cmd`（`HOST=127.0.0.1` と `TRUST_PROXY=cf` を設定して起動する）。

### 公開したときの守り

- 配信するのはゲーム本体（`index.html`）と共有用の画像だけ。ソースや記録の保存先は外から読めない
- 送られてきた記録はサーバーが走りを確かめる（`verify.js`）。載らないもの: 知らないコース／スタートパッドから始まっていない／出口に触れずに次の部屋へ進んだ／ゴールに触れていない／パッドでない場所で復帰した／瞬間移動／人の手では出ない速さ／BOT のタイムの 1/6 未満／長い壁の通り抜け
- 動く障害物へのめり込みが多い記録は「確認待ち」になり、管理者が通すまでランキングに出ない
- ランキングの ID（pid）は最初に使った端末に結びつく。他人の ID を名乗って載ることはできない
- 接続元ごとの回数の上限（確かめられない記録を続けて送る相手は止める）、WebSocket の接続数・メッセージ数・大きさの上限
- ページに書いてあるスクリプト以外は実行しない、通信は自分のホストだけ（CSP）

**限界:** 記録は 30Hz の軌跡なので、1コマ単位の当たり判定までは確かめられません。次のものは自動では防げません。

- 当たり判定を切って、壁はよけながら障害物だけ無視して走った記録。測ったところ、自動で「確認待ち」になるのはそのうち 2〜4 割で、残りはそのまま載ります
- 時間を遅くして走った記録、BOT の道を人並みの速さでなぞった記録

これらは管理者が `sus`（検証で数えた怪しい点の数。正しく走った BOT は 0）を見て消します。公開したら、ときどき表を見てください。

```
set ADMIN_TOKEN=<16文字以上の合言葉>
node scripts/admin.js <サーバーのURL> boards                  表の一覧
node scripts/admin.js <サーバーのURL> board <識別子>           全行（sus と、確認待ちかどうか）
node scripts/admin.js <サーバーのURL> remove <識別子> <pid>    1行を消す
node scripts/admin.js <サーバーのURL> approve <識別子> <pid>   確認待ちの行を通す
```

自分の正しい走りが載らない・確認待ちになるときは、しきい値（`verify.js` の `V`）が厳しすぎます。`VERIFY=0` で検証ごと切れます。

ONLINE（対戦）は、当たり判定とゴールを各自のブラウザが申告する作りのままです。URL を知っている友だちどうしで遊ぶ前提です。

### 保存されるもの

- ブラウザの中（localStorage）: 名前、自己ベストとその走りの軌跡、設定
- サーバー（B の場合）: ランキングに載せた名前・タイム・死亡数・走りの軌跡、ランキングの ID と、それを本人のものと確かめるための合言葉のハッシュ。接続元の IP は保存しない（回数の上限のためにメモリ上で数えるだけ）
- 画面の文字に Google Fonts を使っているので、開いたときに Google へ接続します

## 確認

```
npm test           自動テスト（本体・生成・音・記録の検証・サーバーの守り・ランキング・対戦）
npm run check      上に加えて、実ブラウザ（Edge か Chrome）での通し確認。test-out/ に画面を保存
```

## 中身

1つの `index.html`（素材ファイルなし。絵は canvas、音は WebAudio で合成）と、`server.js`（配信・ランキング・対戦）。設計の経緯は `DESIGN.md`。
